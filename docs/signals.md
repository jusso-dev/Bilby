## Known-good lists and "I know this one" (#18)

These apply after every rule and boost, in `rules::evaluate_all` and `engine::evaluate`. They aren't rules, so they have no fixtures of their own. `crates/bilby-core/src/known.rs` and `tests/suppress.rs` test them, and so do the clean baselines.

- **Known publishers** (`data/known_publishers.toml`, each with where it was checked against a real signed file). A *valid* signature from one of these exact signer names lowers Low or Medium location-based findings (rule ids with `user_writable` or `appdata`) about that file by one confidence level, with an "evidence.known_publisher" line. It also drops `*unsigned*` findings about that file, which can't be right for a signed file. It never lowers masquerading, script-host, `rundll32`, WMI consumer, hosts file, root certificate, driver or reputation findings, or anything not about location (a wrong parent, a duplicate core process). Most location rules already need the file to be unsigned, so today this mainly guards rules still to come.
- **Known startup items** (`data/known_good_items.toml`): updater tasks and services by name prefix, which only match when their file is validly signed by the publisher named in the entry. They label the evidence line; the lowering itself still needs a known publisher.
- **"I know this one"** (`suppressions.json`): the finding stays in the report (`ScanReport.suppressed` lists the ids) and doesn't count toward the light. If the finding's file has a different SHA-256 from when it was ignored, or can no longer be hashed, the suppression doesn't apply and the finding gets an "evidence.changed_since_ignored" line. A file Bilby couldn't fingerprint can't be ignored at all, and an entry for a file finding with no stored hash never applies ("evidence.ignore_unverified"), so a suppression can never outlive the file it was for.
- **Clean baseline** (`tests/fixtures/baseline/`, `tests/baseline.rs`): the windows-latest runner's own snapshot, and a hand-written PC with the apps in `docs/test-plan.md`. Nothing at Medium or above (at Medium confidence or more) may appear unless it's listed as expected with a reason, and the light without those is Looks healthy. On the runner the expected ones are `drivers.test_signing` (High/High: the image boots with TESTSIGNING on), `protection.realtime_off` (High/High: real-time protection is off on the image) and `proc.unsigned_user_writable` (Medium/High: the provisioning agent `provjobd.exe` runs unsigned from Temp). They're true facts about the runner, not false alarms, so no rule is quietened for them. CI also checks each fresh runner dump against `tests/ci-allow.toml`.
