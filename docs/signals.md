# Signals

One row per rule. Filled in by the scan engine issues. A rule can't ship without a row here.

| Rule id | Family | What it means in plain words | Severity | Confidence | False positive notes | Fixture |
|---|---|---|---|---|---|---|
| `protection.no_active_av` | Protection | No antivirus is on: Defender is off or passive, and Security Center lists no other product that's on. | High | High | Defender is passive whenever another AV is primary, so this only fires if no third-party product decodes as on. Silent when Security Center can't be read (Windows Server), because another AV can't be ruled out. Clean machines always have an AV on. | `protection/protection.no_active_av.*` |
| `protection.realtime_off` | Protection | Defender is the active antivirus but real-time protection is off. | High | High | Passive Defender always reports real-time off, so this needs Defender active (on and not passive). Windows turns it back on by itself after a while, so a fresh reading is reliable. | `protection/protection.realtime_off.*` |
| `protection.signatures_stale` | Protection | Defender's virus definitions are more than 7 days old (Medium over 14). | Low / Medium | High | A laptop that was off for a week can hit 7 days, so 7 itself doesn't count, and it stays Low until 14. Ignored when Defender is passive. | `protection/protection.signatures_stale.*` |
| `protection.detection_active` | Protection | Defender found something in the last 30 days that's still active or that it couldn't remove. | High | High | Defender's own verdict. Older unresolved entries are left out because Defender keeps history for a long time. | `protection/protection.detection_active.*` |
| `protection.detection_resolved` | Protection | Defender caught and dealt with something in the last 30 days, and nothing ran. | Low | High | Normal for a working AV (for example a quarantined download). Low, so on its own it never moves the light past Healthy. Silent if anything is unresolved or ran, because a stronger rule covers that. | `protection/protection.detection_resolved.*` |
| `protection.detection_executed` | Protection | Defender dealt with something, but reports it had already run. | Medium | Medium | `DidThreatExecute` can be true for scripts that only opened. An unknown value isn't treated as true. | `protection/protection.detection_executed.*` |
| `protection.tamper_off` | Protection | Defender is active but tamper protection is off. | Low | High | Some managed PCs and older builds have it off on purpose. Silent when Windows doesn't report it. | `protection/protection.tamper_off.*` |
| `protection.third_party_off` | Protection | A non-Microsoft antivirus is registered but reports being off, and Defender isn't covering. | High | Medium | `productState` is undocumented, so Medium confidence at most (issue #7). Silent when Defender is active, for example after a trial expires and Defender takes over. | `protection/protection.third_party_off.*` |
| `protection.firewall_off` | Protection | Windows Firewall is off for a network profile in use right now. | Medium | High | Only current profiles count, so a domain profile that's off on a home network doesn't fire. Silent when a third-party firewall reports being on. | `protection/protection.firewall_off.*` |
| `protection.uac_off` | Protection | User Account Control is off (`EnableLUA` = 0). | Medium | High | The "never notify" slider position leaves `EnableLUA` at 1 and doesn't fire this. Turning UAC fully off needs a deliberate registry or policy change. | `protection/protection.uac_off.*` |
| `protection.updates_old` | Protection | No Windows update has installed successfully for 45 days (Medium at 90). | Low / Medium | Medium | Monthly updates mean a gap of more than 45 days is unusual. An empty history (fresh install, or the history couldn't be read) says nothing. Confidence is Medium because some managed PCs update through other tools that don't write this history. | `protection/protection.updates_old.*` |
| `proc.masquerade.system_name` | Processes | A program with a core Windows name (see `data/windows_core_processes.toml`) is running from somewhere other than its own folder. | High | High (Medium if Microsoft-signed) | The real files only live directly in their System32, SysWOW64 or Windows folder, so a clean machine never produces this. A Microsoft-signed copy in the wrong place is still wrong but less likely to be harmful, so Medium. Silent when the path couldn't be read. Never skipped for a known publisher. | `processes/proc.masquerade.system_name.*` |
| `proc.masquerade.lookalike` | Processes | An unsigned program's name is one edit or a common swap (0/o, 1/l/i, rn/m, vv/w) away from a core Windows name. | High | Medium | Only names of five letters or more are compared, because short names like `dwm` are one letter from too much. Silent for any validly signed file (`service.exe` is one edit from `services.exe`, and real software uses names like that), and silent when the file couldn't be read, because a name alone shouldn't turn the light red. | `processes/proc.masquerade.lookalike.*` |
| `proc.unsigned_user_writable` | Processes | An unsigned or tampered program is running from Temp, Downloads, Desktop, Public, the Recycle Bin or the ProgramData root. | Medium | Medium (High if the signature is invalid) | Signed installers in Downloads, per-user installs under `AppData\Local\Programs`, vendor folders under ProgramData and self-built tools elsewhere are all quiet. | `processes/proc.unsigned_user_writable.*` |
| `proc.unsigned_appdata` | Processes | An unsigned program is running from AppData, outside the per-user Programs folder. | Low | Low (Medium if the same file starts by itself or connects out) | Common for real apps (updaters, helpers), so Low/Low and it never moves the light on its own. It's raised through `RuleContext::related` when persistence or network findings involve the same file. | `processes/proc.unsigned_appdata.*` |
| `proc.core_parent` | Processes | `lsass.exe` or `services.exe` was started by something other than `wininit.exe`. | Medium | Medium | Parent ids get reused, so it's only checked when the parent still exists and started before the child. | `processes/proc.core_parent.*` |
| `proc.core_duplicate` | Processes | More than one `lsass.exe`, `services.exe`, `wininit.exe` or `lsaiso.exe` is running. | High | Medium | Windows runs exactly one of each. Many `svchost.exe` processes are normal and not checked. | `processes/proc.core_duplicate.*` |
| `proc.script_host_encoded` | Processes | PowerShell is running an encoded command (`-EncodedCommand` or any prefix, `-ec`), or a hidden window running download-and-run commands (`iex`, `Invoke-Expression`, `DownloadString`, `FromBase64String` as whole words). | High | Medium | Only PowerShell's own parameters are read: everything after `-File <script>` belongs to the script, so `-File x.ps1 -e foo` doesn't match. `iexplore` and `iexpress` aren't `iex`. Vendor tools commonly use `-ExecutionPolicy Bypass -File`, which doesn't match. `-ex` is not treated as encoded. Command lines are only visible for the current user's processes without admin. | `processes/proc.script_host_encoded.*` |
| `persist.run.unsigned_user_writable` | Persistence | An enabled startup item runs an unsigned or tampered file from a user-writable folder. | Medium | Medium (High in Temp, Downloads, Public or Recycle Bin) | It fires for any user-writable folder: Temp (including `C:\Windows\Temp`), Downloads, Desktop, Documents, AppData, Public, the Recycle Bin, removable drives and files directly in `C:\ProgramData`. Per-user installs under `AppData\Local\Programs` (VS Code, Teams, OneDrive) are excluded, and so is anything in Program Files, Windows' own folders, vendor folders under ProgramData or other non-writable places. Signed AppData apps such as Spotify are quiet. Items turned off in Task Manager drop to Info. It covers files run directly or through `cmd`, `powershell -File`, `explorer`, `msiexec`, local `mshta` and `regsvr32`. A host such as `cmd.exe` or `rundll32.exe` only counts as a host when it's Windows' own copy, so a `cmd.exe` in AppData is the target. Network targets aren't opened. | `persistence/persist.run.unsigned_user_writable.*` |
| `persist.run.script_host` | Persistence | A startup item runs PowerShell with an encoded or download-and-run command, `mshta` with a URL, `regsvr32 /i:` with a URL, or `wscript`/`cscript` with a script from a user-writable folder. | High | High | Vendor scripts run with `-ExecutionPolicy Bypass -File` from Program Files don't match. Uses the same PowerShell parsing as `proc.script_host_encoded`. | `persistence/persist.run.script_host.*` |
| `persist.run.rundll32_user_writable` | Persistence | A startup item uses `rundll32` to load a DLL from a user-writable folder. | High | Medium | `rundll32` with Windows' own DLLs (`shell32.dll,Control_RunDLL`) is quiet. | `persistence/persist.run.rundll32_user_writable.*` |
| `persist.run.missing_target` | Persistence | A startup item points to a file that doesn't exist. | Info | High | Leftovers from uninstalled programs are common and harmless. URLs aren't counted as missing files. | `persistence/persist.run.missing_target.*` |
| `persist.winlogon.shell` | Persistence | Winlogon `Shell` (machine-wide or per user) is something other than `explorer.exe`. | High | High | The full path to `%SystemRoot%\explorer.exe` and any case are accepted. The folder must be `<drive>:\Windows` itself, so `C:\Users\Alex\Windows\explorer.exe` fires. Anything after a comma counts as a change, because it runs too. | `persistence/persist.winlogon.shell.*` |
| `persist.winlogon.userinit` | Persistence | Winlogon `Userinit` is something other than `C:\Windows\system32\userinit.exe,`. | High | High | Case differences and a missing trailing comma are accepted, only under `<drive>:\Windows\System32`. A second program after the comma fires the rule. | `persistence/persist.winlogon.userinit.*` |
| `persist.ifeo.debugger` | Persistence | An Image File Execution Options `Debugger` or a `SilentProcessExit` `MonitorProcess` is set. | Medium (Info for known tools) | Medium (High for known tools) | Developers set these on purpose, so it's Medium/Medium. Process Explorer or the Visual Studio debugger signed by Microsoft Corporation is Info. The same name signed by anyone else stays Medium. | `persistence/persist.ifeo.debugger.*` |
| `persist.appinit` | Persistence | `LoadAppInit_DLLs` is 1 and `AppInit_DLLs` lists something. | Medium | Medium | Rare on modern Windows. Listed DLLs with loading turned off don't fire. | `persistence/persist.appinit.*` |
| `persist.service.user_writable` | Persistence | A service that starts with Windows (or is running) runs a binary or `ServiceDll` from a user-writable folder. | High | Medium (High if unsigned) | Services run as SYSTEM, so anything in a folder an ordinary program can write to is a real privilege risk. Disabled services and drivers (#15) are left out. NVIDIA's `DriverStore` services are under System32 and quiet. | `persistence/persist.service.user_writable.*` |
| `persist.service.unsigned` | Persistence | A service binary is unsigned or tampered, and lives outside Windows' folders and Program Files. | Medium | Medium | Some small vendors don't sign, so Program Files is left alone. User-writable binaries are covered by the High rule above, so they aren't flagged twice. | `persistence/persist.service.unsigned.*` |
| `persist.service.svchost_dll_outside_system` | Persistence | A shared (svchost) service's `ServiceDll` isn't in Windows' own system folders. | High | Medium | Every Windows svchost service keeps its DLL in System32. A few third-party products register svchost services from Program Files, which is why this is Medium confidence. | `persistence/persist.service.svchost_dll_outside_system.*` |
| `persist.service.script_host` | Persistence | A service runs PowerShell with a hidden or encoded command, or a script host, `rundll32`, `mshta` or `regsvr32` with a user-writable target. `cmd /c` is left to `persist.service.user_writable`, so one file isn't flagged twice. | High | High | Vendor scripts run from Program Files with `-File` don't match. Hosts only count when they're Windows' own copy (see `persist.run.unsigned_user_writable`). | `persistence/persist.service.script_host.*` |
| `persist.task.user_writable` | Persistence | An enabled scheduled task runs an unsigned or tampered program from a user-writable folder. | Medium | Medium (High in Temp, Downloads, Public or Recycle Bin) | Per-user installs under `AppData\Local\Programs` are excluded. The OneDrive standalone updater runs from `%LOCALAPPDATA%\Microsoft\OneDrive`, which counts as a per-user install, and it's signed. Google, Edge and Adobe updaters live in Program Files. | `persistence/persist.task.user_writable.*` |
| `persist.task.script_host` | Persistence | An enabled task runs PowerShell with a hidden or encoded command, or a script host or loader with a user-writable target. | High | High | Vendor maintenance scripts from Program Files with `-File` don't match. | `persistence/persist.task.script_host.*` |
| `persist.task.hidden_unsigned` | Persistence | An enabled task outside `\Microsoft\` is marked hidden and runs an unsigned program. | Medium | Medium | Microsoft and Office hide many of their own tasks, so `\Microsoft\` is left out. A COM handler action has no file and doesn't count. | `persistence/persist.task.hidden_unsigned.*` |
| `persist.task.missing_target` | Persistence | A task runs a program that doesn't exist. | Info | High | Leftovers from uninstalled programs are common and harmless. Windows' own tasks under `\Microsoft\Windows\` are skipped, because they can point at optional features that aren't installed. | `persistence/persist.task.missing_target.*` |
| `persist.wmi.command_consumer` | Persistence | A `CommandLineEventConsumer` in `root\subscription` or `root\default` is bound to an event filter. | High | Medium (High with a script host, encoded or download-and-run args, a URL or a user-writable path) | Home PCs rarely have any. The default `SCM Event Log Consumer` is an `NTEventLogEventConsumer`, which is never flagged. Some OEM tools (Dell, HP, Lenovo) register consumers. Planned for #18: documented OEM consumers go on the known-good list and drop to Info. Until then they're reported like any other. | `persistence/persist.wmi.command_consumer.*` |
| `persist.wmi.script_consumer` | Persistence | An `ActiveScriptEventConsumer` (VBScript or JScript) is bound to an event filter. | High | High | Script consumers have almost no legitimate use on a home PC. | `persistence/persist.wmi.script_consumer.*` |
| `persist.wmi.unbound_consumer` | Persistence | A command or script consumer exists with no filter bound to it. | Low | Medium | It can't run on its own, so it's Low. It's usually left over from removed software. Log, file and email consumers aren't counted. | `persistence/persist.wmi.unbound_consumer.*` |
| `net.outbound_from_suspicious` | Network | A process that already has `proc.unsigned_user_writable` or a `proc.masquerade.*` finding has an established TCP connection to a public address. | (boost) | One level up on that finding | No card of its own: it raises the process finding's confidence by one level and adds up to ten connections as evidence. Private, link-local, CGNAT and loopback addresses don't count. No addresses are judged or looked up. | `network/net.outbound_from_suspicious.*` |
| `net.listen_unsigned_user_writable` | Network | An unsigned process in a user-writable folder is listening for TCP connections on a non-loopback address (including `0.0.0.0` and `::`). | Medium | Medium | Signed apps that listen (Spotify on 57621, a signed `node.exe` dev server, svchost on 135 and 445) are quiet. Listening on loopback only is quiet. There's no port list, because ports alone cause false alarms. | `network/net.listen_unsigned_user_writable.*` |
| `net.listen_script_host` | Network | PowerShell, `wscript`, `cscript`, `mshta` or `rundll32` is listening on a non-loopback address. | High | Medium | Script hosts making outbound calls, or listening on loopback (local tooling), are quiet. | `network/net.listen_script_host.*` |
| `net.many_remote_peers` | Network | One unsigned process in a user-writable folder has established connections to 50 or more distinct public addresses. | Medium | Low | Browsers and sync apps talk to many addresses, but they're signed and installed properly. Many connections to one address don't count. | `network/net.many_remote_peers.*` |
| `browser.sideloaded_wide` | Browser | An enabled extension installed outside the store (unpacked, command line, or external location 2, 3 or 6) can access every website. | Medium | Medium | Developers load unpacked extensions, but those rarely ask for every site. Google Docs Offline is an external default without broad access. Component extensions (location 5 and 10) are skipped. Disabled extensions are quiet. | `browser/browser.sideloaded_wide.*` |
| `browser.forced_unmanaged` | Browser | A browser policy force-installs extensions, and the computer isn't Entra joined, domain joined or MDM enrolled. | High | Medium (High if the update URL isn't Google's or Microsoft's store) | Work and school PCs are managed and get `browser.forced_managed` instead. A forcelist entry without an update URL uses the browser's own store. | `browser/browser.forced_unmanaged.*` |
| `browser.forced_managed` | Browser | A forced extension on a managed computer. | Info | High | "Your organisation installed this." Never moves the light. | `browser/browser.forced_managed.*` |
| `browser.shortcut_load_extension` | Browser | A browser shortcut on the Desktop, Start Menu or taskbar has `--load-extension=`. | High | High | Ordinary shortcut arguments like `--profile-directory` and a start page URL don't match. | `browser/browser.shortcut_load_extension.*` |
| `browser.firefox_unsigned` | Browser | An active Firefox add-on installed in the profile has `signedState` below 1. | Medium | Medium | Release Firefox refuses unsigned add-ons, so this is mostly Developer and Nightly editions. Built-in and system add-ons are skipped. | `browser/browser.firefox_unsigned.*` |
| `browser.store_wide` | Browser | A store extension can access every website. | Info | High | Shown under "For your helper" only. Ad blockers and password managers need this, so it never counts toward the light. | `browser/browser.store_wide.*` |
