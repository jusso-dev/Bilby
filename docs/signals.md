# Signals

One row per rule. Filled in by the scan engine issues. A rule can't ship without a row here.

| Rule id | Family | What it means in plain words | Severity | Confidence | False positive notes | Fixture |
|---|---|---|---|---|---|---|
| `protection.no_active_av` | Protection | No antivirus is on: Defender is off or passive, and Security Center lists no other product that's on. | High | High | Defender is passive whenever another AV is primary, so this only fires if no third-party product decodes as on. Silent when Security Center can't be read (Windows Server), because another AV can't be ruled out. Clean machines always have an AV on. | `protection/protection.no_active_av.*` |
| `protection.realtime_off` | Protection | Defender is the active antivirus but real-time protection is off. | High | High | Passive Defender always reports real-time off, so this needs Defender active (on and not passive). Windows turns it back on by itself after a while, so a fresh reading is reliable. | `protection/protection.realtime_off.*` |
| `protection.signatures_stale` | Protection | Defender's virus definitions are more than 7 days old (Medium over 14). | Low / Medium | High | A laptop that was off for a week can hit 7 days, so 7 itself doesn't count, and it stays Low until 14. Ignored when Defender is passive. | `protection/protection.signatures_stale.*` |
| `protection.detection_active` | Protection | Defender found something in the last 30 days that's still active or that it couldn't remove. | High | High | Defender's own verdict. Older unresolved entries are left out because Defender keeps history for a long time. | `protection/protection.detection_active.*` |
| `protection.detection_resolved` | Protection | Defender caught and dealt with something in the last 30 days, and nothing ran. | Low | High | Normal for a working AV (for example a quarantined download). Low, so on its own it never moves the light past Healthy. Silent if anything is unresolved or ran, because a stronger rule covers that. | `protection/protection.detection_resolved.*` |
| `protection.detection_executed` | Protection | Defender dealt with something, but reports it had already run. | Medium | Medium | `DidThreatExecute` can be true for scripts that only opened. An unknown value isn't treated as true. | `protection/protection.detection_executed.*` |
| `protection.tamper_off` | Protection | Defender is active but tamper protection is off. | Low | High | Some managed PCs and older builds have it off on purpose. Silent when Windows doesn't report it. | `protection/protection.tamper_off.*` |
| `protection.third_party_off` | Protection | A non-Microsoft antivirus is registered but reports being off, and Defender isn't covering. | High | Medium | `productState` is undocumented, so Medium confidence at most (issue #7). Silent when Defender is active, for example after a trial expires and Defender takes over. | `protection/protection.third_party_off.*` |
| `protection.firewall_off` | Protection | Windows Firewall is off for a network profile in use right now. | Medium | High | Only current profiles count, so a domain profile that's off on a home network doesn't fire. Silent when a third-party firewall reports being on. | `protection/protection.firewall_off.*` |
| `protection.uac_off` | Protection | User Account Control is off (`EnableLUA` = 0). | Medium | High | The "never notify" slider position leaves `EnableLUA` at 1 and doesn't fire this. Turning UAC fully off needs a deliberate registry or policy change. | `protection/protection.uac_off.*` |
| `protection.updates_old` | Protection | No Windows update has installed successfully for 45 days (Medium at 90). | Low / Medium | Medium | Monthly updates mean a gap of more than 45 days is unusual. An empty history (fresh install, or the history couldn't be read) says nothing. Confidence is Medium because some managed PCs update through other tools that don't write this history. | `protection/protection.updates_old.*` |
| `proc.masquerade.system_name` | Processes | A program with a core Windows name (see `data/windows_core_processes.toml`) is running from somewhere other than its own folder. | High | High (Medium if Microsoft-signed) | The real files only live directly in their System32, SysWOW64 or Windows folder, so a clean machine never produces this. A Microsoft-signed copy in the wrong place is still wrong but less likely to be harmful, so Medium. Silent when the path couldn't be read. Never skipped for a known publisher. | `processes/proc.masquerade.system_name.*` |
| `proc.masquerade.lookalike` | Processes | A program's name is one edit or a common swap (0/o, 1/l/i, rn/m, vv/w) away from a core Windows name. | High | Medium | Only names of five letters or more are compared, because short names like `dwm` are one letter from too much. Silent if the file is signed by a known publisher. | `processes/proc.masquerade.lookalike.*` |
| `proc.unsigned_user_writable` | Processes | An unsigned or tampered program is running from Temp, Downloads, Desktop, Public, the Recycle Bin or the ProgramData root. | Medium | Medium (High if the signature is invalid) | Signed installers in Downloads, per-user installs under `AppData\Local\Programs`, vendor folders under ProgramData and self-built tools elsewhere are all quiet. | `processes/proc.unsigned_user_writable.*` |
| `proc.unsigned_appdata` | Processes | An unsigned program is running from AppData, outside the per-user Programs folder. | Low | Low (Medium if the same file starts by itself or connects out) | Common for real apps (updaters, helpers), so Low/Low and it never moves the light on its own. It's raised through `RuleContext::related` when persistence or network findings involve the same file. | `processes/proc.unsigned_appdata.*` |
| `proc.core_parent` | Processes | `lsass.exe` or `services.exe` was started by something other than `wininit.exe`. | Medium | Medium | Parent ids get reused, so it's only checked when the parent still exists and started before the child. | `processes/proc.core_parent.*` |
| `proc.core_duplicate` | Processes | More than one `lsass.exe`, `services.exe`, `wininit.exe` or `lsaiso.exe` is running. | High | Medium | Windows runs exactly one of each. Many `svchost.exe` processes are normal and not checked. | `processes/proc.core_duplicate.*` |
| `proc.script_host_encoded` | Processes | PowerShell is running an encoded command (`-EncodedCommand` or any prefix, `-ec`), or a hidden window together with download-and-run phrases. | High | Medium | Vendor tools commonly use `-ExecutionPolicy Bypass -File`, which doesn't match. `-ex` is not treated as encoded. Command lines are only visible for the current user's processes without admin. | `processes/proc.script_host_encoded.*` |
